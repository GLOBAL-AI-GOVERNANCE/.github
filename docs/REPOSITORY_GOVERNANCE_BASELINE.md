# Repository Governance Baseline

The portfolio should converge toward these properties where compatible with repository purpose and maturity:

- protected default branch;
- pull-request-based substantive changes;
- no force pushes or branch deletion on protected main;
- read-only default GitHub Actions permissions unless a workflow needs more;
- pinned third-party Actions where practical;
- deterministic or repeatable validation where the artifact supports it;
- explicit security and evidence boundaries;
- repository-local overrides when shared defaults are insufficient;
- version and release claims aligned with the actual repository state.

This document is a maintenance baseline, not a certification standard.
